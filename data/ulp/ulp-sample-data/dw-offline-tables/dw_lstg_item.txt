Overview
In Teradata, this is the hot listing table, containing the most frequently-used fields. Contrary to what this wiki says not all the columns listed here are in this table, for example the FLAGS columns are in DW_LSTG_ITEM_COLD.
In Hadoop, this table has ALL listing items

Column Descriptions
• ITEM_ID
This is the primary key on the table. Item ID uniquely identifies a listing. ITEM_ID is also be referred as LISTING_ID
You can take an item ID and plug it into the end of a View Item link to see the listing (if it's still available on the site). For instance, if you want to look for item ID = 163273736324, just use the following URL:https://ebay.com/itm/163273736324.
Alternatively, just type the item ID into the search box
Apparently a long time ago (~2001?) we were re-using item IDs. Not sure where to look for data that old, but if you do need to go back that far, keep this in mind.

• LEAF_CATEG_ID2
The category ID of the second category chosen by the seller when the seller chooses to list in two categories. The default value for the field (if no second category is chosen) is 0.
• AUCT_START_DT
Date the listing starts.
Note that scheduled listings will exist in the listing table before they are live, so AUCT_START_DT should be used as the date when the listing becomes live.
It would be tempting to assume that AUCT_START_DT <= AUCT_END_DT in all cases, but there are cases where this is not the case (albeit VERY rare cases).
• AUCT_END_DT
This is the date that the listing ended on or is scheduled to end on.
For live eBay items, this date is usually within the next 150 days since the current max duration is SIF 120 days (+ scheduling 30 days in advance?).
SIF GTC (Good 'till cancelled) listings have a revolving 30 day end date, and this field will reflect the end of the current 30 day period. At the end of each GTC period, the end date for a SIF GTC listings will be over-written with a new date 30 days out.
Scheduled listings will have an end date, however be aware that their is no constraint on how far out a listing can be scheduled to start, and hence end.
Half listings essentially "never end", which means that they have AUCT_END_DT values quite far in the future (25 years from the start date appears to be the value for live listings).
This is the date you should use to constrain any queries on the DW tables. This date is used to partition the tables across disks, and so specifying a date will allow your query to run much faster, as well as consume less DW resources.
• AUCT_END_DATE
The timestamp of the listing end time. See AUCT_END_DT for details.
Please note that Daylight Saving Time (DST) can cause time difference between the actual timestamp on the site and the timestamp in the Data warehouse, depending upon the site where the item is listed

• WACKO_YN
Flag that indicates whether the listing is considered a "wacko" listing. SeeListings/Wackofor more details on wacko processing.
The listing-level wacko is flagged based on the following logic when a wacko transaction is processed:
For Chinese auctions, if the transaction is wacko, both the transaction and the listing are marked as wacko.
For Dutch auctions, if any of the transactions for the listing are marked as wacko, then all transactions are marked as wacko, and the listing is also marked as wacko.
For other mulch-quantity listings, if one transaction is marked as wacko, then only that transaction will be marked wacko, and the listing will be marked wacko.
This flag is set by the site at time of EOA.
Because of the above, this flag is NOT the source of record for wacko information. The RPRTD_WACKO_YN field in DW_CHECKOUT_TRANS is the true source of record for wacko information.
• SALE_SCHED_END_DT
Date the listing is scheduled to end.
For scheduled listing, SALE_SCHED_END_DT is set when seller list an item in SYI flow, which equals "sale_start + duration"
For non-scheduled listing, SALE_SCHED_END_DT is set same as SALE_END in EBAY_ITEM table.
This field will not get updated when the listing is ended or checked out
This field is not able to be updated once there is a sale for multi-qty FP/SIF item
This field will only get updated when seller modifies the listing duration or sale_start date in RYI flow when there is no sale.
In DW, SALE_SCHED_END_DT of archived item are set to 1969-12-31. And many half listings will have SALE_SCHED_END_DT in the far future i.e. 2034-01-01

• LSTG_STATUS_ID
Indicates an item's activity status such as live, ended, deleted or archived etc. This column does not exist on the source table EBAY_ITEMS. DW determines a listing item's status based on various logics for different case scenarios.
Potential values: 
0 –Livelistings that are active and searchable on the site (Note: GTC listings which are out of stock are not searchable but still have status 0);
Please note that you also need to consider whether the item is on hold. On-hold listings will still have lstg_status_id = 0, but are not live on site. Please use the ItemOnHold flag stored in FLAGS5 (logic: CASE WHEN CAST(flags5 AS BIGINT) & 1024 = 1024 THEN 'Y' ELSE 'N' END as on_hold);
1 –Endedlistings that are not active on the site;
2 –Admin endedlistings that were ended by CS on the site;
3 –Deletedlistings that are physically removed from the site. Sellers can delete their listings at any time before their listing starts;
4 –Scheduledlistings that are not active on the site yet.
For more details about Admin Ended listings, please seeDataWarehouse/Listings/Archiving.
Listings that end naturally and then are later admin ended (taken down by CS) will have LSTG_STATUS_ID = 1, since they ended naturally.
The logic was adjusted on 2022-01-20 PST, please find details change in PRD

On the Motors site (the primary site for most of the icons), the Icons are shown on ViewItem and in Browse, but not in Search. For the Core Gift Icon, though, it appears in all placements (VI, Search, & Browse). The available icons for a given listing also appear to vary by category of the listing.
Potential values are: ('-99' = None, '0' = None, '1' = 4x4 icon, '2' = Boat icon, '5' = Racing Flag icon, '6' = Hard Hat icon, '7' = Gift icon (Motors), '8' = V8 icon, '9' = Japanese Flag icon, '14' = U.S. Flag icon, '15' = Wrench icon, '16' = Tire icon, '32' = Gift icon (Core & Int'l).

• GMS_USD
This is a calculated field in the DW. It is based off of GMS_EST_LSTG_CURNCY, and is captured once at listing end (and converted based on that day's exchange rate, which is technically not 100% accurate for mulch-quantity listings, but certainly close enough).
The important thing to know about this field is that it's a pretty accurate representation of GMV for alisting, but it makes no statements about thetimingof the GMV. For mulch-quantity purchases, some GMV could have happened in one week/month/year, while other purchases happened much later. That's why technically, accurate GMV calculations must be based onDW_CHECKOUT_TRANS.
Not populated for Ad Format 1.0
Quantity sold and GMV should come fromDW_CHECKOUT_TRANS, as the issue is that data for multi-quantity listings tend to be out of synch in DW_LSTG_ITEM (Updated on 03/07/2011)

• QTY_SOLD
The quantity sold from this listing.
In order to get the quantity remaining on the listing (what some might call the "available quantity"), you must use (QTY_AVAIL - QTY_SOLD).
WARNING: QTY_AVAIL - QTY_SOLD indicated "sale units" remaining, but not the available inventory remaining. To derive inventory counts you need to multiply the remainder by LOT_SIZE fromDW_LSTG_ITEM_COLD. You must use ((DW_LSTG_ITEM.QTY_AVAIL - DW_LSTG_ITEM.QTY_SOLD) * DW_LSTG_ITEM_COLD.LOT_SIZE). • SUCCESS_YN
This is a value calculated by the DW to indicate whether an item has been successful or not.
The logic used to calculate is as follows (as of 3/20/2006):
If the listing has AUCT_TYPE_CODE 2,7,9,12, or 13 (Dutch, SIF, Fixed Price, Half or Lead Generation), then if DUTCH_GMS > 0 and QUANTITY_SOLD > 0, then this flag is set to Y, otherwise it's N.
It appears this flag is set to 'Y' for AUCT_TYPE_CODE 12 only if the listing sells an item on eBay via HalfonCore. While sales on Half.com don't appear to set this flag, more investigation is needed...
If the listing has any other AUCT_TYPE_CODE, then if CURRENT_PRICE > 0 and CURRENT_PRICE >= RESERVE_PRICE and BIDCOUNT > 0 and HIGH_BIDDER <> -1 and QUANTITY_SOLD > 0, then this flag is set to Y, otherwise it's N.
Because of the above logic, it won't be populated for Ad Format 1.0, since ad format items won't have bids.
This is a known issue flag. if you wanna know the success YN, please use the Checkout table. A successful listing is a listing that has a checkout transaction.

• LISTED_WITH_AUTOPAY_UP_FLAG
Indicates whether the listing is an Immediate Pay (/AutoPay) listing.
From the selling flow perspective, when a listing is marked as IP, that means the seller wants the item to be sold only if payment received.
Note that this flag can exist on Auction + BIN listings as well as Second Chance Offer listings, and in neither of those cases does the buyer HAVE to go through the Immediate Pay flow. Check the transaction flag (DataWarehouse/Transactions/DW_CHECKOUT_TRANS.CK_FLAGS2 0x20000000) to determine whether or not the buyer actually checked out via the Immediate Pay flow.
