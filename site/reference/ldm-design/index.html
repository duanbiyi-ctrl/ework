    LDM Design

    This page provides detailed schema information for each LDM (Logical Data Model) in the Item Domain.

    LDM Overview

    In current phase, following the LDM Design Principles strategy of modeling entities as LDMs and relationship data as separate LDMs, the Item Domain LDM design is structured as follows:

    Entity LDMs

    LDM Name Primary Keys Description Physical Sources Priority
    item item_id Core listing entity 11 sources:
    - DIM_ITEM(P1)
    - SLNG_LSTG_SUPER_FACT(P1)
    - DW_LSTG_ITEM(P1)
    - LSTG_ITEM_CNDTN(P1)
    - CTLG_ITEM_FACT(P2)
    - LSTG_ITEM_DESC_DIM(P2)
    - CTLG_PROD_ITEM_FACT(P2)
    - LSTG_ITEM_VIEW_CNTR(P2)
    - DW_LSTG_ITEM_PROD_REF(P2)
    - DW_ITEM_REVISIONS(P2)
    - ITEM360_SRCH_EMBEDDING(P2)
    field-level mapping, one latency per field
    Note: DW_ITEM_REVISIONS → Maps to item_raw view for revision history tracking    		 P1
    variation item_vrtn_id Multi-SKU variations of a listing 2 sources:
    - LSTG_ITEM_VRTN(P1)
    - ITEM360_SRCH_EMBEDDING_VRTN(P2)    		 P1
    product prod_ref_id Product catalog reference (ePID) CTLG_PROD_FACT P2
    transaction item_id, transaction_id Purchase transactions ITEM360_DEALS_TRANS_FACT P2
